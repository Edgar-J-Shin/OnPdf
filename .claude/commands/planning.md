# Role: Senior PM

$ARGUMENTS 에 대한 PRD를 작성한다.

## 프로세스

1. **이슈·브랜치 준비 (git flow)**
   - `git branch --show-current` 가 `develop`/`main` 이거나 이슈 번호가 없는 브랜치면: `gh issue list` 로 해당 작업 이슈를 찾고, 없으면 `gh issue create` 로 만든다 (제목 접두 `M0:`~`M5:`, `--milestone`, 필요 시 라벨). 그 다음 `git checkout develop && git pull && git checkout -b feature/{이슈번호}-{slug}` 로 분기한다
   - 이미 이슈 번호 브랜치에 있으면 그대로 진행
   - 확정된 브랜치명을 `{branch}` 로 쓴다
2. `.claude/workflow/{branch}/` 디렉토리를 확인하여 기존 산출물 파악
3. `pdf-editor-plan.md`에서 해당 기능이 속한 마일스톤(M0~M5)과 완료 기준, 범위 외 항목을 확인한다
4. 코드베이스 탐색 (Explore 에이전트):
   - 관련 기존 모듈(core/edit/app/cli) 파악
   - 유사 기능의 Command·렌더링·저장 패턴 확인
   - 기술적 제약 사항 식별 (PDFium 단일 스레드, 사용 가능한 `FPDF*` API, 폰트/한글 이슈)
5. PRD 작성

## 산출물 구조 (`01-plan.md`)

```markdown
# [기능명] PRD

## 개요
- 목적 / 배경
- 마일스톤: M? / 계획서 완료 기준과의 연결

## 사용자 스토리
- AS-IS → TO-BE
- 핵심 시나리오 (정상/예외: 손상 PDF, 암호화 PDF, 대용량, 한글 문서)

## 기능 요구사항
- 필수 기능 목록
- 우선순위 (P0/P1/P2)

## UI 흐름도 (app 변경 시)
- 화면·도구 패널 변화, 주요 인터랙션

## 비기능 요구사항
- 성능 (첫 화면 1초, 스크롤 끊김 없음), 저장 안정성, 타 뷰어 호환(Adobe Reader·Chrome·Edge)

## 검증 방법
- 단위 / 렌더링 회귀 / 왕복 테스트 중 무엇으로 완료를 판정할지

## 범위 외 (Out of Scope)
```

## 준수사항
- 계획서의 "만들지 않음" 항목을 범위에 넣지 않는다
- 기존 기능과의 일관성 유지 (뷰어, 주석, 페이지 조작, 객체 편집, 저장/실행 취소)
- 기존 코드 패턴을 Explore로 확인 후 PRD에 기술적 방향성 포함

## 완료 후 승인 절차 (필수 실행)

아래 절차를 **반드시** 순서대로 실행한다. 생략 금지.

### Step 1: 완료 보고
산출물 경로와 핵심 요약을 텍스트로 출력한다.

### Step 2: 다음 단계 확인 (AskUserQuestion 필수 사용)
**반드시 `AskUserQuestion` 도구를 호출**하여 사용자에게 묻는다:

- question: "다음 단계를 선택해주세요."
- options: ["다음 단계 진행 (/design)", "수정 후 재실행", "여기서 중단"]

### Step 3: 응답에 따른 분기
- **"다음 단계 진행"** → `Skill` 도구로 `/design` 명령을 **즉시** 실행한다
- **"수정 후 재실행"** → 사용자 피드백을 반영하여 현재 단계 재수행
- **"여기서 중단"** → 워크플로우 중단 안내
